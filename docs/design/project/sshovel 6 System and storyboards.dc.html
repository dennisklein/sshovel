All three surfaces read one StateFlow<TunnelState>; they must never disagree. The status bar key icon appears at ③ (system-drawn).

1 · First run → onboarding → connect → On

  1. H0 Empty home → “Set up sshovel”
  2. O1 Welcome → O2 key created (StrongBox)
  3. O3 Copy authorized_keys line → install on server
  4. O4 Server, subnets, DNS
  5. O5 Trust this server → snackbar “Server trusted” → O6a test passes
  6. O7 Add tile → system prompt → O8 Tile added
  7. O9 Connect now → V1 → system VPN dialog → H2 → H3

3 · Tile tap without VPN permission

  1. Tile “Off” tapped. VpnService.prepare() ≠ null → tile stays Off, shade collapses
  2. V1 opens over the current app → Continue
  3. System dialog → Allow → app returns to H2, tile “Connecting…” → H3, tile “Office”
  4. Deny → V2 “VPN permission needed” → Try again re-launches the system dialog

4 · Wi-Fi → mobile data while On

  1. H3 On over Wi-Fi
  2. Default network changes → SSH read times out → H4 Reconnecting (retry 2 s, 4 s, 8 s…). Tile “Reconnecting…”, notification “Retry now”. TalkBack: “Reconnecting to Office. Next retry in 8 seconds.”
  3. Retry succeeds on mobile data → H3; uptime resets, traffic counters continue. TalkBack: “Connected to Office”.
  4. No network at all → detail “No network. sshovel will reconnect when you’re back online.”; waits for onAvailable instead of retrying.

5 · Host key changed

  1. Connect → H2 “Checking server identity”
  2. Mismatch → tunnel stops, state Needs attention; tile “Tap to fix” (attention icon); problems notification “Server identity changed”
  3. If the app is foreground: S4 opens immediately. Otherwise the notification or tile opens it.
  4. Disconnect or back → H6. “Review in profile” → P2 → Forget pinned key (P7) → next connect shows S3.

6 · wiki.corp.example fails in the browser

  1. Chrome shows a connection error. User pulls down the notification → “Diagnostics” (or Home → troubleshoot)
  2. G2 DNS: wiki.corp.example → 10.20.7.15, Tunnel, 14 ms — DNS is fine
  3. Connections tab badge “1” → G3: 10.20.7.15:443 · Chrome · “Refused by server policy” with next step: ask the admin
  4. Variant: the name resolves outside routed subnets → warning row in G2 tells the user which /32 to add
